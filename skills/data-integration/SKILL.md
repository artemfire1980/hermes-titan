# Data Integration — Связка внешних источников с МойСклад

## When to Use

Использовать когда нужно объединить данные из разных источников: почта + МойСклад, CRM + Excel, внешний API + внутренняя база. Ключевая задача — установить связи между объектами из разных систем.

## Ключевые ограничения МойСклад API

**Важно:** MCP-инструменты МойСклад имеют критические ограничения для интеграции:

1. **`id` возвращается, если указать в `fields`.** MCP `get_resources` возвращает только запрошенные поля. Чтобы получить `id`, добавьте его: `fields=['id','name','inn','email',...]`. **Прямая связка по UUID работает:** `counterparty.id` = `customerorder.agent.id` = `demand.agent.id`.
2. **Лимит 1000 объектов** — `get_resources` возвращает максимум 1000 записей. Если возвращается ровно 1000 — данных больше.
3. **Только read-only** — нельзя писать данные, только читать.
4. **Топ-клиенты не в почте** — крупные оптовые клиенты (топ по salesAmount) обычно работают через телефон/WhatsApp, а не через email. Их может не быть в переписке artem_s@chocoladovo.by.
5. **Email — 63.1% (1699 из 2694).** `counterparty.email` — 34.9% (940), `contactpersons[].email` — ещё 28.2% (759). Всего 2369 уникальных email. Для рассылки — `/mnt/ai-ssd/hermes/cache/moysklad-audit/email_base.txt`.

## Стратегии связки (по убыванию надёжности)

### 1. Email domain match (высокая точность)
- Сравнение домена из email заголовков с полем `email` в МойСклад
- Работает когда в МойСклад заполнен email контрагента
- Точность: ~95%
- Покрытие: 34.9% через counterparty.email, 63.1% с contactpersons

### 2. INN match (высокая точность)
- Сравнение ИНН из документов с полем `inn` в МойСклад
- Точность: ~98%
- Проблема: ИНН редко встречается в текстах писем (только в приложениях)

### 3. Contact name match (средняя точность)
- Нормализация имён: удаление префиксов (ООО, ИП, АО), пунктуации
- Сравнение подстрок
- Точность: ~70%
- Нужна осторожность с ложными срабатываниями

### 4. Domain word match (низкая точность)
- Поиск слов из домена в названии компании
- Много ложных срабатываний ("bank" → "Сбербанк", "Росбанк", "Русский банк")
- Использовать только как подсказку

### 5. Ручной маппинг (100% точность)
- Создание файла mapping.json с парами (домен ↔ контрагент)
- Required для топ-20 активных компаний
- Сохранять в /mnt/ai-ssd/hermes/cache/spillover/

## Workflow

1. **Экстракция доменов** из внешнего источника
   - Из писем: domain = часть после `@` в from/to/cc
   - Игнорировать публичные домены: mail.ru, gmail.com, yandex.ru, outlook.com, corp.mail.ru, id.mail.ru

2. **Получение данных** из МойСклад
   - `get_resources(key="counterparty", fields=["name", "inn", "email", "salesAmount", "tags", "description"])`
   - Сохранять в spillover для анализа

3. **Анализ покрытия** перед матчингом
   - Проверить % контрагентов с email (2026-10: 34.9% напрямую, 63.1% с contactpersons)
   - Проверить топ-10 по salesAmount — есть ли у них email?
   - Осознать: топ-клиенты по продажам могут НЕ быть в почте

4. **Матчинг** по стратегиям выше
   - Сначала email domain (высокая точность, низкое покрытие)
   - Затем contact name с нормализацией
   - Затем domain word (осторожно, много ложных)

5. **Ручная проверка** несвязанных топ-компаний
   - Создать mapping-файл для top-20 активных в почте
   - Использовать теги из МойСклад для подтверждения гипотез
   - Проверять description на наличие подсказок

## Теги как ключ к пониманию

Теги в МойСклад — основной способ сегментации клиентов:
- `самсонов`, `демух`, `богданович`, `ерашов` — кто ведёт клиента (менеджер)
- `глазури`, `кондитерка` — тип продукта
- `покупатель`, `поставщик`, `перевозчик` — роль в цепочке

Использовать теги для проверки гипотез при матчинге.

## Формат mapping-файла

```json
{
  "logiterra.ru": {
    "mcp_name": "Название в МойСклад",
    "mcp_inn": "1234567890",
    "match_type": "manual",
    "confidence": 0.9,
    "notes": "Партнёр по логистике, тег: перевозчик"
  }
}
```

## Pitfalls

- **Не гадать** — если нет данных для связки, сказать «нет данных», не выдумывать соответствие
- **Проверять теги** — тег "перевозчик" может означать что домен логистической компании, а не клиента
- **Учитывать лимит 1000** — если контрагентов больше, top по sales может быть обрезан
- **Email не гарантирует связь** — топ-клиенты по продажам могут работать через WhatsApp/телефон, не через email
