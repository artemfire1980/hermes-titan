# Бенчмарк памяти Hermes

**Дата:** 2026-09-26
**Контекст:** CP-008 — выбор external memory provider

## Built-in memory (baseline)

| Параметр | Значение |
|----------|----------|
| Файлы | `MEMORY.md` + `USER.md` |
| Расположение | `/mnt/ai-ssd/hermes/memories/` |
| Memory injection | ✅ enabled |
| User profile | ✅ enabled |
| Memory tool | ✅ enabled |
| External provider | (none) |

**Built-in работает всегда**, независимо от external. Baseline — уже
функционален.

## Доступные external providers

| Провайдер | Тип | API key | Локальный | Статус |
|-----------|-----|:-------:|:---------:|:------:|
| `holographic` | Bundled | ❌ | ✅ | Готов |
| `byterover` | Bundled | ✅ | ⚠️ | Нет ключа |
| `honcho` | Bundled | ✅ | ⚠️ | Нет ключа |
| `mem0` | Bundled | ✅ | ⚠️ | Нет ключа |
| `openviking` | Bundled | ✅ | ⚠️ | Нет ключа |
| `retaindb` | Bundled | ✅ | ⚠️ | Нет ключа |
| `supermemory` | Catalog | ✅ | ❌ | Требует подписки |

## Решение

**Оставляем built-in** как основной провайдер.

**Причины:**
1. Built-in работает и покрывает базовые потребности (факты, профиль пользователя).
2. Все внешние провайдеры требуют API-ключей, которых нет.
3. `holographic` — локальный, но требует тестирования; отложим до реальной необходимости.
4. Minimal-surface: не тащим компонент, который не решает конкретную проблему.

**Когда вернёмся:**
- Если built-in не покроет долгосрочную память между сессиями.
- Если понадобится семантический поиск по прошлым диалогам.
- Когда появятся ключи для mem0 / honcho / retaindb.
