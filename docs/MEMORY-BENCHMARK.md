## Решение

**Оставляем built-in** как основной провайдер.

**Причины:**
1. Built-in работает и покрывает базовые потребности (факты, профиль пользователя).
2. Все внешние провайдеры требуют API-ключей, которых нет.
3. `holographic` — локальный, но требует тестирования; отложим до реальной необходимости.
4. Minimal-surface: не тащим компонент, который не решает конкретную проблему.

**Когда вернёмся:**
- Если built-in не покроет долгосрочную память между сессиями.
- Если понадобится семантический поиск по прошлым диалогам.
- Когда появятся ключи для mem0 / honcho / retaindb.

**Результат: 5/5 через перефразированные запросы.**

### Вывод

**Holographic достаточен** для текущих задач:
- Bundled (переживёт `hermes update`)
- Локальный (без ключей, без сервера)
- ARM64 (работает на VIM4)
- Semantic recall 5/5
- RAM/CPU минимальные (SQLite)
- Built-in параллельно, без конфликта

**OpenViking не требуется.** Отложен как опция для будущих задач
(например, если понадобится L0/L1/L2 hierarchical retrieval для большого
корпуса документов).

### Что НЕ подошло

- **Hindsight** — отклонён (DEC-024): ARM64-проблемы, `hindsight_client` через PM.
- **OpenViking** — отложен: +1 сервер, AGPL-3.0, RAM TBD. Не оправдан, пока
  Holographic справляется.
- **OMEGA** — не Hermes provider (MCP-интеграция мимо штатного механизма).
- **Mastra OM** — TypeScript framework, не drop-in provider.
